# Adaptive RAVEN 第二轮诊断结果分析

日期：2026-10-02（北京时间）。结论：**任务已经停止，完整优化计划没有跑完；速度有积极信号，质量与截断优化尚未通过验证。**

## 1. 完成范围与停止原因

后台于 2026-10-02 10:11:54 停止，状态 `STOPPED_PROTOCOL_ERROR`，退出码 2、NRestarts=0。
完成 9 次诊断请求：旧 Adaptive D3 四次、未启用保护的 anchor D4 四次、旧配置同题重跑一次。
当前没有后台请求在运行。

停止检查为：同一配置、同一题目、同一种子，在重启并改变之前请求的顺序后，输出必须一致。
题目 7311、实际 seed=73153，两次均正常答对 95，但输出为 **592 vs 1700 token**，
耗时 **213.0 vs 564.1 秒**，控制器因此停止。这是复现检查失败，不是本轮质量门槛判定。
没有记录到 OOM 导致此次停止；日志明确给出 `Same configuration/seed replay differs`。

尚未执行：delta=0 GPU 诊断、独立顺序 Target 回放、单因素短测、保护策略选参、
24 题完整回归、留出校准、Native/Cactus/SpecCascade 正式对照。
三个新保护/加速开关的 CPU 测试通过不能替代这些实机阶段。

## 3. 复现失败最早发生在哪里

从最后一个请求的逐轮记录对齐得到：

1. 第一验证轮的 token、P/Q 和接受随机数相同。
2. 第二轮（已生成 3 token），同一二层主路径 token 的 Target 概率相同：**0.439356**；
   接受随机数也相同：**0.289195**；但草稿 Q 从 **0.250476** 变为 **0.213698**。
3. 第 23 轮，三层草稿 token 首次不同，两条验证路径仍提交相同 token，但一次全部接受、
   一次拒绝后通过 residual hit 提交。因此后续随机数消耗路径不再相同。
4. 第 24 轮接受随机数已经不同；第 25 轮，已生成 88 token 时，实际输出块首次不同。
   两段文本有 370 个相同开头字符。

因此只重置请求局部备选 RNG 没有充分恢复复现；**最先需要查的是草稿 Q 对同一前缀的依赖**，
包括分支拓扑/计算行数、MTP 缓存与状态复用、请求边界及前缀缓存。
此前服务存在前缀缓存命中，而重启的服务起初没有命中，这是候选因素，尚不能据此确认为根因。
真实 head 探针 logits 最大绝对差 0.0625，也不能仅凭三个 warmup 输入就排除数值影响。

当前日志没有完整 Q 向量、备选构树轨迹、hidden/KV 指纹和各处 RNG 状态，
不能确定 Q 差来自数值误差还是状态/缓存错误。不能把这种差异直接解释为数学准确率下降，
也不能绕过检查后将后续差异全部归因于方法参数。

## 4. EOS 保护的证据与局限

未启用保护时，已访问的主路径中确实观察到 EOS 质量下降。例如 anchor D4：

| 题目 | 已生成 token 数 | Target EOS 总概率 | 松弛后 EOS 总概率 | 被接受的草稿 |
| --- | ---: | ---: | ---: | --- |
| 2629 | 351 | 0.6970 | 0.0472 | 换行 |
| 2950 | 703 | 0.9369 | 0.5949 | 换行 |

这说明放大非 EOS 候选可能显著降低 EOS 质量，支持单独验证 EOS 保护。
但以上两题最终都正常结束，不能把这两条观测当作截断原因的直接证明。

真正截断的 anchor D4 7300、7311 请求，已访问主路径的 Target EOS 总质量最大都只有约 **1e-9**；
旧 D3 截断的 2950、7300 最大分别约 **1e-6、1e-9**。
固定阈值 0.5 的 EOS 保护不会在这些已记录位置触发。
统计仅覆盖实际访问的主路径，不包含完整顺序 Target 重放或每个备选分支。

**推断：仅保护已经明显想结束的 Target，无法覆盖模型持续重复复核而尚未支持 EOS 的情形。**
需要同时验证更保守的松弛设置与重复风险检测；收益必须通过完整请求测量。

## 5. 重复检测目前覆盖不足

现有重复检测要求 4–64 token 的后缀块连续完全相同三次；所有诊断记录的该标记均为 false。
但文本中明显存在反复复核：旧 D3 截断的 2950 有 12 个重复句段的额外出现，
anchor D4 截断的 7311 有 7 个。
句段统计按标点/换行分段并压缩空白，是辅助启发式，不是精确 token 重复指标。

**推断：当前检测对短句改写、相同结论穿插其他解释不敏感。**
下一步应先用 train 回放评估滑动窗口内非连续重复 n-gram/句段，再考虑风险位置降低松弛；
必须测正常推理的误触发，不能把合理复核全部当成循环，更不能靠硬停答案掩盖截断。

## 6. 下一步优先顺序

1. 给相同前缀的草稿计算补充 Q/hidden、拓扑、KV 与 RNG 指纹；用独立进程与同进程改变请求顺序复测。
2. 前缀缓存开/关分别诊断，保持所有对照一致；只有证据指向某项机制才修改，不把缓存开关直接当作已确认修复。
3. 完成独立顺序 Target 对照，排除状态/停止语义问题后再测试保护策略。
4. 改善重复检测覆盖，并按原计划逐项测试 delta/head/构树/深度；质量与速度门槛通过后继续留出及三基线正式测试。

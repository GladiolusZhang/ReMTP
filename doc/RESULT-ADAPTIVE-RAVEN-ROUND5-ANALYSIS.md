## 3. EOS保护真正改变了什么

### D3候选：缩短部分回答，没有减少截断

相对旧D3，43/48条输出逐字相同；另外5条文本改变，但**每一条的判对与结束类型都不变**。
其中4条已经正常结束且正确的回答缩短：

| 题目 / 基础种子 | 旧输出token | 新输出token | 变化 |
| --- | ---: | ---: | --- |
| 1019 / 42 | 1568 | 1461 | 少107 |
| 4741 / 42 | 637 | 498 | 少139 |
| 4911 / 42 | 1288 | 569 | 少719 |
| 1231 / 43 | 1780 | 1583 | 少197 |

总计少1162 token，下降3.07%。题1532/42文本改变，但仍2048 token截断且答错。
9条旧截断请求全部仍截断，**本轮D3没有救回任何截断题**。

### Anchor候选：只修复上一轮的一条截断

相对上一轮失败anchor，47/48条输出逐字相同。唯一改变是6530/seed43：
2048 token截断→937 token正常结束，明确答案`#### 7`仍正确。
因此截断9→8、正常结束且判对37→38，但原判对仍42。
这是一条真实改进，不能推广为解决主要退化。

## 4. 两条故障现场对机制的判断

重放门槛四项全部通过，说明本次两条退化可以稳定复现。
两题的候选诊断输出与它们随后无探针回归的文本/结束类型一致，观测没有改变已核对的现场输出。

| Anchor故障题（seed43） | 观测结果 | 对EOS假设的判断 |
| --- | --- | --- |
| 1231 | 179 token正常结束，答案100，gold120；阈值改为0.01后输出完全相同。访问主路径最高EOS质量约0.999984，原保护已激活 | 这是正常结束的解题错误，增强结束保护无法修复其计算/理解 |
| 5180 | 两配置都2048 token截断，文本完全相同。所有访问主路径诊断行的最高Target EOS质量仅约2.218×10⁻⁷，没有一行达到0.01 | 该轨迹本身几乎不给EOS质量，阈值0.01保护没有激活；此现场不支持“中等EOS质量被压低”解释 |

旧D3两题存在2条EOS质量≥0.01且受压低的主路径记录；增强保护后变为0。
但旧D3这两题原本都正确且正常结束，保护后仍如此，仅1231回答缩短。
因此“EOS质量压低机制存在”与“它导致主要失败”需要分开：
**本轮支持其局部作用，没有支持它是Anchor质量退化的主要原因。**

仍需保留其他解释：更早的近似验收/树结构改变可能让轨迹进入反复推理，
也可能涉及模型自身采样行为。两种结构间所有48条输出不同，且同时存在深度、top-k、
松弛、anchor与重复保护等配置差异，尚不能将错误单独归因于其中任何一个。
本轮没有重新定位数值算子；继承的是已通过且源码/协议一致的有限数值覆盖。

## 5. 速度是否达到目标

- old_eos01平均整题耗时减少**2.91%**，主要对应回答token减少3.07%；
  E2E吞吐实际下降约**0.16%**，p95基本相同。因此只观察到少量回答更早结束，
  没有观察到单位token解码更快；若加回吞吐门槛，它会因`all:throughput`未通过。
- anchor4_eos01平均整题耗时比旧D3少**21.52%**，输出token少16.79%，
  E2E吞吐高约**6.02%**；但质量门槛失败，不能选它作为达标结果。
- 按24题聚类、连同两个种子、2000次bootstrap的训练描述性吞吐比95%区间：
  old_eos01为[0.9953,1.0008]，未支持明确吞吐提升；Anchor为[1.0371,1.0757]。
  参照来自上一轮、未交错重跑，区间不能消除设备/时间差异，也不是正式独立test结论。
- old_eos01所有本样本判对状态都相同，bootstrap判对差为0不能证明真实未来正确率完全相等；
  48条请求只有24道题，两个种子不是48道独立题。
- 本轮没有与Native、Cactus、SpecCascade在同一独立样本上对照，尚不能声称超过三个基准。

## 6. 下一步建议

1. 将old_eos01保留为质量保守的研究参照，继续记录EOS保护的局部收益；
   不以训练门槛通过或平均回答缩短作为最终算法成功证据。
2. 优先定位Anchor在1231/43、5180/43等失败题的**最早路径分叉**：
   沿同一实际前缀检查Target P、draft Q、实际松弛TV、accept/reject与选择token，
   查清进入错误回答/反复推理之前的决策。保持完整预算，避免只检查最后一个数字。
3. 用旧D3作为起点做有限单因素消融，分别考察深度、anchor与松弛设置；
   无依据继续降低EOS阈值，可能只增加严格验收成本，不能保证改变错误推理。
4. 质量候选稳定后执行独立留出，再冻结设置与三个基线进行同题、多种子、轮换顺序正式比较。
   同时考察正确率、正常结束且判对、截断、吞吐和整题时间。

本次仅完成结果核查与分析归档，没有启动新一轮GPU测试。

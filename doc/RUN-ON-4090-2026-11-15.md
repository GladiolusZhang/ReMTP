# 在 4090 上直接运行本分支（2026-11-15）

- 仓库：`https://github.com/GladiolusZhang/ReMTP`
- 分支：`jetson-r39-residual-adapt`
- 代码就在仓库根目录：`remtp/`（方法实现）、`scripts/`（启动和对比脚本）、`tests/`（测试）、`doc/`（说明和结果）。
- 方法说明和改动清单见 `doc/PORTING-RAVEN-V4-2026-11-14.md`；实验数据见 `doc/RESULT-RAVEN-V4-TARGET-GATE-2026-11-13.md`。

## 1. 取代码

```bash
git clone https://github.com/GladiolusZhang/ReMTP.git   # 已有仓库则 git fetch origin
cd ReMTP
git checkout jetson-r39-residual-adapt
git pull
```

## 2. 环境、模型和数据

```bash
./scripts/install.sh                      # x86 上安装 vLLM 0.18.0 到 .venv
source .venv/bin/activate
pip install pytest huggingface-hub        # 测试和下载模型用
./scripts/download_fastmtp.sh             # BF16 FastMTP -> models/FastMTP
./scripts/download_humaneval.sh           # -> data/humaneval/HumanEval.jsonl.gz
docker pull python:3-slim                 # HumanEval 判分沙箱
```

本分支要求 vLLM 0.18.0（CUDA graph、树注意力的补丁都针对这个版本）。

## 3. 先跑测试

```bash
python -m pytest -q tests/                # 一定要带 tests/，不带路径会遍历 results/ 等大目录
```

Jetson 上是 703 项通过、1 项跳过。GPU 相关的测试（`test_tree_cudagraph.py`、`test_gpu_tree.py`、`test_async_host.py` 中的 CUDA 部分）在 4090 上也会运行，它们检查的是"逐位相同"，如果失败请先告诉我。

## 4. 一键对比四种方法

```bash
scripts/run_compare.sh
```

- 依次启动 AR（`target`）、Native、Cactus、RAVEN v4-safe 的服务。每种方法用同一批 HumanEval 题目、同样的种子和输出上限跑完，停服务，用 Docker 判分。
- 最后打印并写出 `results/compare_<时间>/compare.md`：pass@1、MAL、每轮秒、decode tok/s、端到端 tok/s、截断数、相对 AR 的倍数。
- 默认 100 题、输出上限 512、温度 0.6。常用调整：

  ```bash
  METHODS="cactus raven" SAMPLES=30 scripts/run_compare.sh   # 只比两种方法、30 题
  OUT=results/my_run scripts/run_compare.sh                  # 指定输出目录；中断后重跑会跳过已完成的方法
  SKIP_EVAL=1 scripts/run_compare.sh                         # 不判分，只看速度
  ```

- 每种方法的目录里有 `server.log`，逐题记录和 `summary.json` 在其下的 `humaneval/`。

## 5. 单独起某一种方法的服务

```bash
scripts/serve_compare.sh raven            # 或 target / native / cactus；默认端口 8000
```

然后用 OpenAI 接口请求（模型名 `TencentBAC/FastMTP`），或者另开终端运行：

```bash
python -m remtp.humaneval_benchmark --model TencentBAC/FastMTP --run-name raven \
  --samples 30 --temperature 0.6 --max-tokens 512 --output-dir results/raven_30
python -m remtp.humaneval_evaluator results/raven_30
```

## 6. 配置说明

`scripts/serve_compare.sh` 给四种方法同样的设置：

- 注意力都用 Triton 内核（`TARGET_ATTENTION_BACKEND=TRITON_ATTN`）；
- 同一组目标数值开关；
- 一次一个请求，不用前缀缓存；
- 使用 no-think 模板。

RAVEN 是 v4-safe 配置：

- 树 D3/N9；
- 主干上只在目标概率 p ≥ 0.01 时松弛；
- 每个位置的接受概率不超过 Cactus。

可用环境变量调整：

| 变量 | 默认 | 作用 |
| --- | --- | --- |
| `ENGINE_OPT` | `1` | 工程配置：所有方法用完整 CUDA graph（不经过 torch.compile）和自旋等待；RAVEN 另加可捕获的树注意力、异步主机读、GPU 建树。设 `0` 则全部 eager。前两项（CUDA graph、自旋）不改变输出 |
| `GPU_BUILD` | `1` | RAVEN 的 GPU 建树。与 `0` 相比，决策逻辑相同，但约 18% 的题会在较后的位置因浮点最后一位不同而分开（见下） |
| `SPIN_WAIT` | `1` | 等待 GPU 时自旋。是为 Jetson 的 CPU 调频加的；4090 主机若 CPU 调频器是 `performance`，开不开都一样 |
| `MODEL_PATH` | `models/FastMTP` | 模型目录 |
| `QUANTIZATION` / `LOAD_FORMAT` | 空 | 4090 用 BF16 不需要设；若用 W4A16 GPTQ 则设 `gptq_marlin` / `auto` |
| `PORT`、`MAX_MODEL_LEN`、`GPU_MEMORY_UTILIZATION` | `8000`、`4096`、`0.85` | 服务参数 |

启动后可在 `server.log` 里确认：

- 有 `Graph capturing finished`（CUDA graph 生效）；
- RAVEN 有 `target_gate_min_p=0.01` 和 `adaptive_max_ratio=1`（v4-safe 生效）；
- RAVEN 有 `device-side tree construction`（GPU 建树生效）。

## 7. 需要知道的几点

- **GPU 建树与逐 token 一致性**：在相同输入下，GPU 建树与主机建树的决策完全相同（校验模式 `REMTP_DYNAMIC_TREE_GPU_BUILD_CHECK=<文件>` 可逐层核对）。但 MTP 层只有 1 行输入时，cuBLAS 选的内核和多行时不同，最后一位会变，偶尔会改变一次采样。Jetson 上 HumanEval-100 有 82 题输出逐 token 相同，MAL 和 pass@1 不变。需要严格逐 token 复现时设 `GPU_BUILD=0`。
- **Jetson 上的结果**（HumanEval-100，输出上限 512，W4A16 GPTQ 模型）：

  | 方法 | pass@1 | MAL | decode tok/s |
  | --- | ---: | ---: | ---: |
  | Cactus | 55/100 | 3.090 | 24.68 |
  | RAVEN 主机建树 | 57/100 | 3.246 | 22.82 |
  | RAVEN GPU 建树 | 57/100 | 3.252 | 23.59 |

  4090 的 GPU 和 CPU 都快得多，吞吐比例需要实测。
- **不适用于 4090 的脚本**：
  - `scripts/ab_canonical_tree_attention.py` 和 `scripts/run_w4a16_maxn_suite.py` 依赖 Jetson 本地、不在 git 里的冻结环境文件（`results/raven_full_100x100_20261010/`），4090 上请用 `scripts/run_compare.sh`。
  - `scripts/serve_fastmtp_jetson.sh` 是 Jetson 专用的。
- **分析工具**（只在设置环境变量时生效，不影响结果）：
  - `REMTP_ROUND_LOG_JSONL`：逐轮验证日志，配合 `scripts/analyze_suite_round_logs.py`；
  - `REMTP_GPU_EVENT_TIMING_JSONL`：各模型部分的 GPU 时间；
  - `REMTP_HOST_TIMELINE_JSONL`：主机时间线，配合 `scripts/analyze_host_timeline.py`。

## 8. 2026-11-16 更新（4090 上的后续工作）

- 默认的兄弟选择阈值改为 `TREE_KAPPA=50`、`TREE_TAU_MIN=1e-6`（原 1.5、0.001）：熵阈值实际失效，每层总保留 2 个兄弟
  （主干被拒后命中兄弟的概率由 0.65/0.59/0.50 提高到 0.74/0.68/0.62）。接受规则、松弛额度与树预算不变。可用这两个
  环境变量恢复旧值。
- `ASYNC_SCHED=1`：所有方法使用 vLLM 异步调度；RAVEN 另外把每一轮留在 GPU 上（设备端建树与验证、固定 9 槽容量、
  融合 kernel）。验证的随机数每轮固定消耗，分布不变、具体样本改变。默认 0。
- `scripts/run_compare.sh` 支持多个数据集：`DATASETS="humaneval gsm8k mbpp"`。MBPP 用 `remtp/mbpp_benchmark.py`
  生成、`remtp/mbpp_evaluator.py` 在 Docker 中判分（test split 11–510，三条官方断言）；数据由
  `python -m remtp.router_benchmark_download` 下载并校验 sha256。例：

  ```bash
  DATASETS="humaneval gsm8k mbpp" SAMPLES=50 MAX_TOKENS=2048 ASYNC_SCHED=1 scripts/run_compare.sh
  ```
- 实验性：`CATERPILLAR=j`（只提议主干和每层 j 个兄弟，容量 3+3j，需 `ASYNC_SCHED=1`）。
- 详细记录见 `docs/research_and_development_log.md` 2026-11-15/16 各条。

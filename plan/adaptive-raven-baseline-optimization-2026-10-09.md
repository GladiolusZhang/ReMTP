# 以原 Adaptive RAVEN（B）为基准的优化计划

> 用户目标更新（2026-10-09）：不要求避免截断，只以正确率与速度超过三个基准判断。[新执行计划](adaptive-raven-dominance-2026-10-09.md)已替代下文截断/正常结束/逐题硬门槛、单候选限制及强制F→E顺序。下文保留为制定时的历史计划；新独立搜索采用另行登记额度。

日期：2026-10-09（UTC+8）。状态：**第 1 步研究完成；后续实现与 GPU 单元待执行。**

目标：同一模型、设备和协议下，正确率及正常结束判对不低于 Native/Cactus/SpecCascade，减少截断，同时提高 token 吞吐并缩短整题耗时。保留 B 作方法参照，最终用独立题集验证。

依据：[本轮真实分叉、失败机制与新研究](../doc/RESEARCH-RAVEN-BASELINE-2026-10-09.md)。上轮 target_odds 已拒绝；[完整负结果](../doc/RESULT-RAVEN-TARGET-ODDS-2026-10-09.md)保留。

## 失败原因转化成具体要求

1. **约束信号误伤：**不继续搜索 p/p_max 两档阈值或 cap2。当前同种接受翻转既改善又退化，新质量设计先验证算法输出律。
2. **门槛覆盖不足：**开发集固定 8 题×2seed：1532、2950、6009、3213、1231、5180、308、641。B 的所有正常结束判对配对为回归哨兵，保留所有已判对配对的损失检查，不能净数抵消。
3. **观测位置不准：**从 API 首差异登记请求级窗口；最多 8 个完整 verifier/raw 帧及 3 个配套 proposal 窗口，保存真实位置和 bookkeeping 对应关系，不再仅依赖统一稀疏 checkpoint。
4. **速度收益不够：**先按真实成本优化；B 追平 Cactus 至少需 +10.62% 吞吐，MAL不变近似轮成本 -9.60%；单独 top-k 或少一次 MTP 调用不足以保证达标。
5. **结束机制未证明：**单个 H(EOS) 不保证整体输出 EOS；完整 KL 或同前缀 EOS 约束也不保证整题准确与不截断。纳入末段轨迹和完整质量门槛。

## E：B 计算优化的验收

先完成 CPU 依赖/槽映射审查，只实现一个默认关闭计算候选。保持主干/树选择、Q/H、head0和RNG调用次序；稳定物理槽避免后加入 sibling 改变祖先地址，逻辑 RoPE 位置仍由深度决定。不能直接删除最终物化或把不同树的 KV 当顺序缓存。

首GPU边界：16个预登记真实帧×B/候选，共32条件replay；B/候选各6自然请求，共12主HTTP；2启动/2预热，12小时，0重试。早/晚、接受/拒绝/命中/未命中均需覆盖。

32条件replay仅运行已有P/Q上的verifier与RNG，不添加模型前向；不能验证新proposer。新MTP的隐状态/KV与真实P/Q来自12自然请求的预登记实际窗口，比较相同提交前缀，原始缓存地址与逻辑位置分别记录。

门槛：真实隐状态、KV、P/Q/H、候选、随机数末状态、提交IDs逐位相同；6请求完整输出相同。少一个查询行数引起数值变化也算失败。条件帧重放不能代替完整自然请求证明。

通过后才登记无探针计时；目标≥5%相对B的实测吞吐收益作为计算阶段筛选，整体三基准胜出仍要求更高收益。若前沿物化不能保持等价或收益不足，本候选停止，保留原B。

## Q0/Q1：唯一质量候选的研究与验证

Q0仅CPU数学研究：同前缀构造 EOS 质量与 P 一致的 Qbar，H_beta=(1-beta)P+beta Qbar，按完整 KL 预算确定 beta；预算不读取当前抽到哪个候选及其未来路径。原 delta=1/深度权重作一次预登记起点，不做阈值网格搜索。它是对B预算机制的研究修改，要单独标记方法名并做消融。

要求：证明候选留存不改变真实 Q、残差命中后仍先采 correction 再查 sibling、anchor 用原 P、完整 H 不依赖当前候选；枚举候选输出边缘、EOS、KL、零概率、组质量为0/1等边界。需要任何不成立的假设就停在Q0。

Q1在Q0通过后实现默认关闭候选并登记：16帧×B/候选=32 CUDA 条件检查；8题×2seed×B/候选=32主HTTP；2启动/2预热，12小时，0重试。前4个回归请求先跑原B正常结束判对哨兵，出现新增判错或停止转截断即保存并停止，不以另一条改善抵消。

先完成原B16条，再启动候选；候选首先运行2950/42、1231/42、6009/43、641/43四条哨兵，随后优先检查3213/43。CUDA条件检查也仅为verifier，不包含隐藏的额外模型调用。按真实输入输出确认本单元Q条件律及全部H约束，不能从16帧推断所有自然状态都已数值证明。

开发门槛：总体与每seed原判对/正常结束判对不降、所有原B已判对配对无新增判错、原B正常结束判对哨兵无损失；截断相对B严格减少；候选吞吐/平均整题不恶化。完整KL、EOS局部性质通过不能替代这些任务门槛。

## 最终联合门槛与独立评测

- 五方法开发比较：原B、单一组合候选、Native、Cactus、SpecCascade，各16，共80无探针主HTTP，5启动/5预热，24小时，0重试。不同代码或公共环境变化不能复用旧基准计时。
- 在当前16条刻度上，原判对至少14、正常结束判对至少11、截断少于5、吞吐高于2.8932、平均整题低于368秒，才有超过三个基准的初步证据；实际比较还需总体/每seed相应门槛及回归哨兵全部通过。工程争取吞吐比最快基准+5%。这些数字不作为独立题集的固定得分标准。
- 独立留出在以上全部通过后一次登记20道从未用于诊断/选策略的训练题×2seed×五方法=200主HTTP，分两个10题单元，各100HTTP/5启动预热/24小时，0重试。取样前列出所有历史观察IDs与数据hash，固定选择规则；结果不可回流调参后仍称留出。
- 留出通过后冻结正式100道未观察test题×3seed×四主方法=1200HTTP，拆为12个预登记10题单元，每单元100HTTP、4启动预热、24小时、0重试。若历史test已观察则排除；题数或预算不足需明确报告，不能用已观察题补齐正式样本。
- 每次四方法一致prompt、模型、精度、温度、输出预算、数值实现；按题聚类报告正确率/正常结束判对/截断、吞吐、平均/P95耗时。预设论文门槛为候选对每个基准质量差值点估计及95%区间下界不负、吞吐比95%区间下界>1、整题平均更低、截断更少；样本不够或区间未过只能报告证据不足，不降低门槛或无限追加题目。

## 1. 目标与固定条件

目标：Adaptive RAVEN 对 Native、Cactus、SpecCascade 的原判分正确率和正常结束判对均不降低，截断更少，token 吞吐更高、平均整题耗时更低。uniform RAVEN 用于消融。

- 保持 FastMTP FP4 Target + BF16 MTP/head0、软件版本和公共数值路径。
- 保持原 prompt/no-thinking/评分器、temperature0.6、4096 上下文、2048 输出上限、TP1、单请求、1 GiB KV、prefix cache 关闭。
- 首轮采用 B：D3/N9、head 行批1、现有 adaptive 和 EOS0.01；懒残差/cap2 默认关闭。Cactus delta1、SpecCascade TokenV3 alpha0.5；读取实际生效配置确认。
- profile 的 64-token 输出仅作算子诊断；质量比较全部使用 2048 输出预算。
- 每一新单元独立冻结、独立目录、Restart=no、有限预算，不在运行中的冻结代码上打补丁。

## 3. 第二单元：以保持语义的计算优化为主

依据第一单元 profile，在下列方向中最多选择一个：

| 方向 | 实施重点 | 必须先证明 |
| --- | --- | --- |
| MTP 树计算复用 | 复用同轮累计节点、父隐藏与重复 logits；保留必要最终 KV 物化 | 相同输入/位置/祖先、完整 Q、隐藏与 KV 读写、提案顺序/概率、CUDA RNG 和提交状态 |
| 归一化/同步合并 | 合并逐行检查或重复归一化，减少非必要 CPU scalar 转移 | 不改变有效 P/Q/H、NaN拒绝、防护规则、接受/残差/bonus 抽样与 RNG |
| 后剪枝/精确 top-k | 保持原构树/预算决策后裁剪，或相同稳定 ties 的候选选择 | live GPU 提案、P/Q、位置/KV、接受路径/terminal/RNG；不能只用本次保存张量 CPU 检查 |

只有当前 profile 支持预计整体收益有意义，才进入实机验证；以≥5%为努力目标。若收益上限很小，保留为普通清理，不安排长回归来包装核心加速。

后剪枝曾降速，重试必须解释当前 padding/算子路径有什么可验证的变化。MTP 增量计算可能因 GEMM 形状、覆盖顺序或 KV 行重映射改变数值，不能直接删掉累计/最终 pass。

### 验证与预算

1. 先完成小词表、真实张量、ties、有限性、RNG和边界的必要CPU验证；不跑无关测试。
2. 注册最多16个比较案例×B/候选两次，共32个顶层CUDA验收/重放调用。包含根/备选、拒绝命中/未命中、EOS/budget和晚段状态。case scope、输入hash和实际调用先冻结。
3. 2条8-token短请求与2条2048自然请求，B/候选同题同seed比较；检查有/无探针不改变输出/RNG。额外观测不改变采样次数。
4. 通过后，新同源 B/候选各24训练题×3种子，共144条无探针请求。seed顺序42 B→候选、43候选→B、44 B→候选；旧B仅作历史稳定性对照，新速度必须同源重跑。
5. 对计算优化要求所有输出/token IDs/finish/原判分逐条一致，且速度有收益。若不一致，停止“语义不变”声明，定位，不把质量总分相同当作等价。

本单元最多148条主HTTP、32顶层CUDA调用、8次服务预热；最多1个计算候选，72小时上限，失败无自动重试。启动前建立独立policy；未启动前不计为已执行。
